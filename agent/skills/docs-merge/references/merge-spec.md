# docs-merge 合入规范

主干：[SKILL.md](../SKILL.md)。流程：[workflow.md](workflow.md)。

## 1. 解析 source / target

1. 收位置参与可选 `--dry-run`。
2. **target**：须已存在 `.md`；不存在 → 中止。无法判定谁是 target → 停问。
3. **source**：已存在文件 → 读全文；否则内联文本。路径/正文两可或像拼写错误 → 停问。
4. 单参且像已存在 md → candidate target，补收 source。

## 2. 切分源块

按源内 H2/H3 切块；无标题则整段一块（落位必问）。块内列表/表/代码围栏原样迁入，除非目标节要求改写。

## 3. 落位（H2/H3）

1. 规范化标题（去编号、空白、大小写折叠）比对目标树。
2. 唯一命中 → 计划落位该节。
3. 多候选 / 无候选 → 停：候选或新建（可改标题、挂靠父级）+ 数字选项。

未落位须在**写前澄清**收口。未落位非空 → 不得给正式写入的写前 `C`（dry-run 可展示未落位计划）。

## 4. 类似判定（同节内）

| 条件 | 计划标记 |
| --- | --- |
| 无标题近似且无关键句/实体明显重叠 | **新增** |
| 标题规范化相等或词重叠达近似 | **更新**（合并候选） |
| 无标题但关键实体/状态/API 等重叠显著 | **更新**（合并候选） |

边界不清 → 标 **更新·待确认**，勿静默当无关新增。

## 5. 变更清单（清点）

落位与类似判定完成后、正式逐项确认前，须先输出 **变更清单**：

```text
待确认变更清单
- 待新增：<A> 项
- 待更新：<U> 项
- 合计：<N> 项（未落位：<M>，须为 0 才进入正式写入确认）
```

可选附编号索引（一行一项：`#i · 新增|更新 · <落位章节> · <标题/摘要>`），**不含全文**。

**硬规则**：须先公布项数与清单，再进入 §6 逐项提问；禁止跳过清点直接问单项或落盘。

## 6. 逐项提问确认（新增 / 更新）

写前 `C`（正式写入）且变更清单已出后，按 [grilling-skill.md](../../../references/grilling-skill.md) **以提问方式**处理清单中每条 **新增**、**更新**：

**硬规则**

- **确认完一条再流转下一条**；收到用户对本项的明确答复后，才进入 `i+1/N`。
- **一次只问一项**；禁止把多项合成一题，禁止决策表一次性待批。
- 禁止默认全采纳。

**每项提问结构**（对齐 grilling fallback）：

```text
[变更 i/N · 新增|更新] <落位章节>
预览：<拟写入或 diff 摘要>
问题：<本项是否采纳？如何处置？>
推荐：<采纳|跳过|修改后采纳> + 简短理由
选项：
1. <推荐项>
2. <备选项>
…
```

**更新**项若含事实/表述冲突 → 在本项内继续提问（嵌套 `k/M`）；**该项未决完不得进入下一项**。

仅**已确认项**进入落盘集。

## 7. 落盘

1. `--dry-run`：合入计划 + **变更清单**（待新增/更新项数）；**不写文件**。
2. 正式：落位已确认 + 写前 `C` + 变更清单已出 + **逐项提问已全部答完** + 项内冲突已决 → **一次**写回 target（仅落盘集）；失败整文件回滚。
3. **不改源**。
4. 禁止：未清点、未确认项落盘、边确认边写、打包「全部直接写」。

## 8. knowledge 目标

target 在 `application|system|company` 下 `*/knowledge/**` 时：正文/链接/路径字面量守 [knowledge-governance.md](../../../knowledge/knowledge-governance.md)「业务 knowledge 引用边界」。库外文档链 → 留字去链；无 parent 的跨层 → 纯 ID；不明则停。
